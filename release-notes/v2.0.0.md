## The launch check is now two skills

`pre-launch-check` did two jobs: it checked that a site was ready to go live and that it was secure. It is now split in two, and no check is in both.

- **`pre-launch-check` became `launch-check`.** It keeps the readiness checks: staging URLs, search and analytics, redirects, forms and email, a real purchase, test content, privacy, licences, mobile speed, and the backups with a restore drill. That is 17 checks. Its script, `scripts/go-live-check.sh`, now runs the setup pass only.
- **`launch-security-check` is new.** It checks the site from the outside: 19 checks, from two-factor sign-in, HTTPS and security headers to locked staging copies, email and DNS. `scripts/check.sh` runs the checks a machine can run, and `FIXES.md` has a fix for each failed check.

## Run order

1. Run `launch-security-check` first. It needs no access to the site and no owner.
2. Run `launch-check` second. It reuses the host list the security check gathered.

Each skill gives its own GO or NO-GO. The site is ready when both say GO. Both scripts exit 0 on GO, 2 on NO-GO and 1 on an error.

## If you installed `pre-launch-check`

The name `pre-launch-check` is gone, which is why this is 2.0.0. Remove the old folder and install the pair:

```sh
npx skills add shahpahlevan/skills --skill launch-security-check
npx skills add shahpahlevan/skills --skill launch-check
```

`register-site`, `wp-cli-safely` and `migrate` are unchanged.
